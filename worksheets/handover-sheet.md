# Pause and hand over a signal task

This sheet records what people know when a practice session pauses or roles change. It does not preserve game progress, control a save file, or imply that a game supports reconnecting at any particular point.

## Outgoing pair's record

| Question | Note |
|---|---|
| Which agreement/table were we using? | |
| What was the last choice confirmed by both people? | |
| Was any message sent but not confirmed? | |
| Was an action already taken on that message? | |
| Which observations are uncertain? | |
| Where did numbering start, and whose viewpoint was used? | |
| What needs checking before continuing? | |

If the last confirmed state is unknown, write “unknown.” Do not promote an unfinished exchange to confirmed during handover.

## Incoming pair's check

- [ ] We have the same choice ordering and signal table.
- [ ] We agree what the stop signal cancels.
- [ ] We can distinguish the chosen channels in the current setting.
- [ ] We have demonstrated one known choice in each direction.
- [ ] We have either resolved the unfinished exchange or explicitly discarded it.

Resume point agreed by both people: __________

If the checks disagree, return to a state both people recognise. Rehearse there before continuing. A change of table, choice order or viewpoint should be treated as a new agreement, even when the people and puzzle are unchanged.

See the [shared agreement](agreement-sheet.md) and [observation log](observation-sheet.md). These documents support discussion; they do not collect data, measure performance, or assert a universal communication method.
